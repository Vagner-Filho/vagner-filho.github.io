> OVERVIEW

When I use AI here, I mean LLMs / Generative techniques. Humans have relationships with objects, we can attach sentiment and have stories about a screwdriver, a pen, a car or any inanimate object. Given that fact, people can misplace what an AI is, under or over estimating it. Regulating its capabilities and usage can be hard and dependent on what you want to get from it.

Using it to learn something means that it is a support tool, helping with organization, fetching information, building a quiz or explaining something, whereas using it to generate assets such as code, image or text, means that it is a working tool. In both and any cases where AI is generating content, the human operating it is responsible for checking its output since they can and do, hallucinate, producing false information to blindly satisfy the input.

> USAGE

As a tool, it has the right time and place to be used. In my workflow, I use it to explore codebases, scaffold template code, build POCs, implement / refactor code blocks I am a specialist on, so that I can validate its output confidently. The more complex it gets, the less likely I am to use it: First, I want to exercise my creativity. Second, this is where it gets closer to hallucinate, since the issue is not present enough in its training dataset.

The combo Playwright failure prompts + Kimi K2.6 works very well. It succeeds most of the time in providing a correct analysis and solution to the issue either for a test problem or a real bug. In my usage of Cypress, there are no such failure prompts and the usage of AI to help with the tests is much less useful.

I also use Google's Stitch to scaffold UIs and explore ideas, then create a design skill file or use the provided DESIGN.md file to give agents the ability to consistently implement UI elements that match a system's styling and patterns.
